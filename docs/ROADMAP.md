# Implementation roadmap

Each phase ships as a working system with migrations, tests, docs and a phase report. Nothing from a later phase is stubbed early.

| Phase | Scope | Main deliverables | Status |
|---|---|---|---|
| **1 Foundation** | Monorepo, backend, Postgres, Prisma, Redis, auth (OTP / email / Google / Apple), RBAC, users, pets, species/breeds, admin auth, flags, settings, audit, CI, Docker | `apps/backend`, 2 migrations | ✔ Delivered |
| **1b Admin dashboard** | Next.js admin dashboard: sign-in, overview, people, pets, species/breeds, roles & permissions, features & settings, audit log, search | `apps/admin-dashboard`, 9 browser tests | ✔ Delivered |
| **2a Social core** | Storage + signed uploads, media worker (images, HLS video), posts/reels, likes, saves, shares, views, comments, hashtags, feeds, blocking, reports, moderation API | migration `social`, worker | ✔ Delivered |
| **2b Notifications + moderation UI** | Notifications (in-app, grouped, preferences, FCM push, devices, @pet mentions), moderation queue in the dashboard | migration `notifications`, 2 new screens | ✔ Delivered |
| **2c Customer app** | Flutter customer app: sign-in, pets, feed, reels player, upload, comments, notifications, settings | `apps/customer-mobile` (contract-verified, not yet compiled) | ✔ Delivered |
| ~~2 Social~~ (split above) | StorageProvider + signed uploads, posts/reels, video pipeline (BullMQ + FFmpeg → HLS), likes, comments, saves, shares, hashtags, feed, block/report, moderation queue, push (FCM), notification preferences; Flutter customer app (auth, pets, feed, reels) | worker app, customer-mobile | |
| **3a Contest engine** | Categories, builder, lifecycle with legal gate, Razorpay/fake payments with verified webhooks, registration with capacity locking, submissions, public voting with fraud holds, weighted judging, frozen leaderboard, winners, cancellation refunds queued | migration `contests`, payments module | ✔ Delivered |
| **3b Contest screens** | Dashboard: contest list, builder, control room (lifecycle, legal review, money and what-if, leaderboard and entry decisions, held-vote review, freeze, winners, special awards), categories. App: contests, entry with Razorpay checkout, task submissions, voting, leaderboard | dashboard + app | ✔ Delivered |
| **3c Challenges** | Challenges (free, paid, contest-linked), daily check-ins in India time, streaks, bonus points, badges, rankings; contest notifications (entry, voting, results); judging screen in the app | migration `challenges`, dashboard + app | ✔ Delivered |
| **4a Services API** | Partner onboarding with private KYC documents and admin review, categories and commission, PostGIS nearby search, slots in India time with staff capacity, exclusion-constraint double-booking protection, payment holds, refund policy, reviews, notifications | migration `services` | ✔ Delivered |
| **4b Services screens** | Dashboard: verification queue, partner review with per-document decisions and signed links, commission, categories, bookings with filters and admin cancellation. App: services near you (or by city), partner page, slot picker in India time, species-aware booking with checkout, my bookings, cancel, review | dashboard + app | ✔ Delivered |
| **4c Partner app** | Onboarding, KYC upload, services, hours and time off, bookings calendar, start, complete or no-show, earnings | service-partner-mobile | ✔ Delivered |
| ~~3 Contests~~ (split above) | Contest builder and lifecycle, finance config per contest, legal-review gate, registration + Razorpay, tasks, submissions, public votes with anti-fraud, judges and weighted criteria, leaderboard (Redis sorted sets + frozen snapshots), winners, prize workflow, challenges, streaks, badges | contest engine | |
| **4 Services** | PostGIS, locations, partner onboarding + document verification, services, availability calendar, slot locking (no double booking), bookings, cancellation policies, reviews, partner app | service-partner-mobile | |
| **5a Marketplace API** | Vendor onboarding with private KYC and GST checks, categories with commission, products and variants with GST-inclusive prices, cart, coupons (platform- or vendor-funded), checkout split into a parcel per vendor, race-safe stock reservation, payment holds and late-payment revival, fulfilment with tracking, cancellations and returns with refunds queued, vendor earnings, notifications | migration `marketplace`, marketplace module | ✔ Delivered |
| **5b Marketplace screens** | Dashboard: vendor verification, products moderation, orders, coupons, categories, settings. Customer app: shop, product page, cart, checkout with coupons, orders, cancellations and returns | dashboard + customer-mobile | ✔ Delivered |
| **5c Seller app** | Store onboarding with KYC upload, seller home (to-do, sales windows, stock alerts), products with photos and variants, stock, orders to pack and ship with tracking, cancellations, returns, seller-funded coupons, earnings | product-partner-mobile, seller API additions | ✔ Delivered |
| **6a Finance core** | Double-entry ledger with database guards (balanced, one-sided, append-only, idempotent), postings for every money event, commission GST, TCS and TDS (PAN-aware), refund execution through the gateway (idempotent, backoff, webhooks, polling), payment status from refunds, nightly reconciliation with repair and missed-capture recovery, finance reports, monthly TCS/TDS report, seller and partner statements, Finance role | migration `finance`, finance module, worker jobs | ✔ Delivered |
| **6b Payouts and invoices** | Payout accounts (encrypted, bank-validated, safety hold), maker-checker payout batches through RazorpayX (fake for development), webhooks, bounced and reversed payouts, contest entry-fee revenue and cash prizes with TDS, gateway settlements and fees, seller/partner tax invoices, credit notes, PetApp commission invoices, PDFs | migration `payouts`, finance module, worker jobs | ✔ Delivered |
| **6c Finance screens** | Dashboard: finance overview, refunds, reconciliation issues, payout batches (prepare / approve), payout accounts, prizes, settlements, invoices, tax report, trial balance | dashboard | ✔ Delivered |
| **6d Money in the apps** | Seller and partner apps: statement, payouts, payout account, invoices. Customer app: refund status and invoices. Winners: payout account | apps | ✔ Delivered |
| **7a AI moderation and risk** | AI provider (built-in rules, or Claude), background checks of posts, comments, profiles, listings, reviews and contest entries with every result stored (labels, confidence, reason, model, version), cases for moderators (AI never decides), optional hide-while-waiting, copied-photo fingerprints, account fraud-risk scores with staff review and held votes, dashboard screens | migration `ai`, trust module, worker queue | ✔ Delivered |
| **7b Recommendations** | Recommended products, services, contests and reels (pet species, breed, age, location, history), admin-controlled home sections | migration `home_reco`, recommendations module, dashboard Home screen, customer app Home tab | ✔ Delivered |
| **7c PetApp Assistant** | In-app assistant for services, products, contests, challenges and navigation, with veterinary guardrails, behind ENABLE_AI_ASSISTANT | migration `assistant`, assistant module (tools, guardrails), AssistantProvider, dashboard page, customer app chat | ✔ Delivered |
| ~~7 AI~~ (split above) | AI moderation assist (never final), recommendations, PetApp Assistant with vet-advice guardrails, fraud scoring | AIProvider | |
| **8a Observability and security** | JSON logs with request ids, error tracking, Prometheus metrics (API, worker, queues, payments), alert rules, System health page, fraud and security test suite and fixes (vote race, instant sign-out, search wildcards) | observability module, security.e2e | ✔ Delivered |
| **8b Privacy and legal** | Data export, account deletion job (anonymise where records must be kept), consent records, legal documents managed in the dashboard (privacy, terms, contest, refund, cancellation, partner, vendor, community), marketing consent | privacy module, apps | ✔ Delivered |
| **8c Public web and deep links** | SEO pages for pets, products, services, contests and reels (Open Graph, structured data, sitemap, robots), legal pages, app links (petapp:// and https) | web app, apps | ✔ Delivered |
| **8d Launch readiness** | Backups and restore drill, load tests, CI security scans, deploy pipeline, store builds and crash reporting, runbooks, final production checklist | `scripts/ops`, `load/`, `infrastructure/deploy`, security and deploy workflows, mobile release workflow, runbooks | ✔ Delivered |
| **9a Chat and support** | Chat between customers and service partners or sellers (text, private photos, booking/product/order cards, report and block, live over WebSocket, push), support center (FAQs, topics, tickets with priority and six statuses, staff replies and notes, staff-started conversations), NestJS 11 | migration `chat_support`, chat module, dashboard Support pages, chat and help screens in all three apps, push in the partner and seller apps, website /help | ✔ Delivered |
| **9b Reviews and reporting** | Product reviews from delivered orders (verified purchase), photos on product and service reviews, star breakdowns, replies from sellers and partners, review moderation, reporting every kind of content with screenshots, the reports dashboard | migration `reviews_reports`, reviews module, dashboard Reports and Reviews pages, review and report screens in all three apps, ratings on the website | ✔ Delivered |
| **9c Search, discovery, locations** | Global search across pets, people, reels, products, services, businesses, contests and challenges with per-kind filters; pet discovery (trending, opt-in nearby pets, popular reels, contest and challenge entries); the location database (states, cities, areas, PIN codes on PostGIS) with CSV import; delivery zones at checkout; service coverage; partner locations | migration `locations_search` (pg_trgm), locations, search and discover modules, dashboard Locations section, app search, Discover and PIN lookup | ✔ Delivered |
| **9d Analytics, memberships, reminders** | Admin analytics for users (daily and monthly active, sign-ups, retention), reels (views, completion, engagement), contests, the shop and services, with CSV export; membership plans (Free, Plus, Premium; off by default) with members-only contests, premium challenges, member coupons, priority booking and a member badge; booking, contest and membership reminders; vote updates; opt-in promotions | migration `analytics_memberships`, analytics, memberships and reminders modules, worker jobs, dashboard Analytics, Membership and Promotions pages, app Membership screen and new notification settings | ✔ Delivered |
| **9e Staff passwords and uploads** | Staff password change, forgot-password and admin-sent reset links by email (SMTP provider), password rules; resumable video uploads in parts with retries and resume after a dropped connection; presigned-upload checksum fix | migration `passwords_uploads`, email provider, staff password service, media multipart endpoints, dashboard Forgot password / Your account pages, app resumable uploader | ✔ Delivered |
| **10a Two-factor sign-in for staff** | Authenticator-app codes (TOTP, RFC 6238) at dashboard sign-in, ten single-use recovery codes, replay protection, admin reset, and an optional rule that every staff member must use it (`security.requireStaffMfa`) | migration `staff_mfa`, StaffMfaService, `/admin/auth/login/mfa` and `/admin/auth/mfa/*`, dashboard sign-in code step and Your account panel | ✔ Delivered |
| **10b Offline and errors in the apps** | Saved copies of key screens shown offline with a notice, reads retried after a dropped connection, payments the gateway took while the API couldn't be reached confirmed later, friendly error messages that never show server internals (spec §84–85) | customer app ApiClient, offline cache, pending payments, offline banner; the same in the partner and seller apps | ✔ Delivered |
| **Final: maps and spec sign-off** | `MapProvider` (none, Google Geocoding) with place search by PIN code, city, area or landmark, and named positions; the spec §85 messages; the §86 production checklist and §89 deliverables checked one by one (`docs/FINAL-VERIFICATION.md`) | maps provider, `/locations/search`, app place search, `docs/FINAL-VERIFICATION.md` | ✔ Delivered |
